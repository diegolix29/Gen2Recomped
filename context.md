# Repository Context — gen2rec (Gen2Recomped)

## Overview
- Native LÖVE2D (Lua) recreation of Pokémon games, decoded from a player-supplied ROM (no ROM shipped, no emulation). Fork of bryanthaboi/gen1recomp, by UNDERdecodedHD.
- Started as Gold/Silver/Crystal on the Gen 1 engine; now also runs FireRed/Emerald (Gen 3, Alpha), Platinum/HGSS (Gen 4, Pre-alpha), Black/White (Gen 5, Pre-alpha), Polished Crystal and Prism. Also Monster Walker, Map Editor, Save Editor, translation, cloud saves, DS dual-screen, touch.
- Supported dumps are pinned by SHA-1 (table in README.md, details in docs/rom-revisions.md).
- License: source-available "Gen2Recomped License" (LICENSE.md), no redistribution / commercial use.

## Git
- Remote: `G2` = https://github.com/diegolix29/Gen2Recomped (there is no `origin`).
- Main branch: `main`. Active branch (2026-10-28): `gen5-fixes`, tip 4512eefb "Rebase new emerald voxels"; it sits 2 commits past main's 8d5b4387 (fff10edc, 4512eefb).
- Many old feature branches (COLO-*, FIX-BUILDINGS, Fixing-Carpet, ...).

## Architecture
- Entry: `conf.lua` (save identity "Gen2Recomp" on desktop, "pokemon-love2d" on mobile; `--editor` / `--developer` flags or env POKEPORT_EDITOR / POKEPORT_DEV) then `main.lua`. `manifest.lua` is large (~336 KB).
- Import: `src/import/RomImporter.lua` + `RomExtractor.lua` verify the ROM and write a private cache (data/generated/*.lua, assets/generated/**). Gameplay reads only the cache.
- `src/` areas: audio, battle (Gen1–Gen4 battle/anim modules), cloud, contest, core (Game, Data, ChipAudio, FixedStep 60 Hz, StateStack, SaveData), dev, import, inventory, link (lua-enet P2P), mods, net, pokemon, pokewalker, render, save_convert, script (ScriptRunner coroutines + Commands), translation, ui, update, world (Map/Player/NPC/Warp/Encounter plus per-game modules such as Gen5*.lua).
- Map scripts are hand-ported in `data/scripts/<map>.lua`.
- Mods: `mods/`, bundled ones in `bundlemods/` (BATTLE_CINEMATICS, Kanto-in-Motion, red_3d_player, wild_skies, ...); see docs/modding.md.
- Docs: `docs/architecture.md` plus many per-feature parity notes (emerald-*, gen2-*, platinum-*, hgss-bw-import.md, emerald-voxel-performance.md).
- Misc folders: `Claude outputs/` (earlier AI notes), `cmd runs/`, `Python/`, `ports/`, `mobile/`.

## Dependencies
- LÖVE 12.0-development nightly (pinned in scripts/love12-runtime.json); LuaJIT / Lua 5.1 semantics (CI also uses lua5.4).
- Python + Pillow for the developer data path `tools/build_data.py`.

## Build / Run / Test
- Windows dev launch: `Play-Windows.bat` (sets POKEPORT_DEV=1 and runs scripts/bootstrap.ps1). Setup: scripts/setup.ps1; run: scripts/run.ps1 (prefers lovec.exe for console output).
- Packaged exe build: scripts/build-windows-exe-script.ps1 (output Gen2Recomped.exe in the repo root). Other targets: build_android, build_ios, build_msix, build_switch, build_xbox_uwp, build_linux_arm64, build-rg34xxsp.sh.
- Tests: `scripts/test.sh` (tiers T1–T5; `--quick`, `--bless`). Lint: scripts/lint.sh (.luacheckrc).

## Colosseum cache packing (lib/CacheArchive.lua, PACK CACHE menu)
- Units: <save>/cbe_cache_archive/{pokemon,movefx}/<key>.cbeu (zlib per file), index cache/archive_v1/<kind>.lua, readEntry reads one entry straight from its unit (no loose copy). Auto-pack: species/moves written by the extractor or GeneratedAssets.write are packed in the background (A.tick from BattleRuntime, 20 s settle). Must be loaded BEFORE BuildPipeline.run (main.lua creates it early). Identity files that code reads via mod.cache directly stay loose (pinnedLoose): manifests, movefx index/coverage, per-species model_cache.lua / rev.txt / extract.txt.
- Where: units in C:/Users/<user>/AppData/Roaming/LOVE/Gen2Recomp/cbe_cache_archive/ (pokemon/<dex>_normal|shiny.cbeu, movefx/<stem>.cbeu); index in modstorage/DRAMATIC_SHAPE/cache/archive_v1/{pokemon,movefx}.lua. The two belong together: delete both or neither.
- GeneratedAssets hooks (A.install): info, read, write (marks auto-pack), revalidateInfo (model library texture checks / disk-cache count) all fall back to the archive.
- Status 2026-10-31: confirmed working in game by the user (packed cache loads, model library prepares).
- ORAS models have their own kind (oras -> cbe_cache_archive/oras, index archive_v1/oras.lua, row ORAS PACK) -- see the ORAS section.
- Moving a packed install (e.g. to an Android custom game-data folder): copy cbe_cache_archive/ AND modstorage/DRAMATIC_SHAPE/cache/archive_v1/*.lua(.bin) AND build/cache_archive_*_v1.complete (+ *_report) from the SAME pack; units without their index read as no cache. Fixed this way on the user's phone 2026-11-01 (Documents/Gen2).
- Custom game-data folder: src/import/CacheFs mounts it for reads as a union with the save dir; on Android (JNI love.system.mountDirectory) it is APPENDED, so the internal save dir wins any path both have. mod.cache (index, markers) follows the chosen folder; CacheArchive's unit writes still use love.filesystem (internal save dir) -- being changed in a separate session (CacheArchive writes through CacheFs.dataFs).
- A.repairLostEntries (startup, once): drops index entries whose unit cannot be opened, then writes build/cache_archive_repair_v1.complete. Since 2026-11-01 it leaves the index alone when NO listed unit can be opened (folder missing or not mounted), keeps the repair pending and logs a warning.

## ORAS import (Terrarium Advance Mod, bundlemods/Terrarium Advance Mod/)
- Player-supplied decrypted Omega Ruby / Alpha Sapphire dump, launcher import id `pokemon_oras` (file pokemon_oras.3ds), read in slices by lib/N3DSRom.lua. Built from OPTIONS -> ORAS MODELS (lib/ORASModels.lua); lib/ORASProbe.lua writes survey reports (mod cache oras/probe.txt, oras/export.txt).
- Models: GARC a/0/0/8 (lib/GARC.lua). Member 0 = index (4 bytes per species: u16 first form, u8 forms, u8 flags); form f block starts at member 2 + 8f. Block slots: +1 model BCH, +3 textures, +4 shiny textures, +6 battle motions (GF1Motion), +2 face/eye anim. Gen 6 model names are internal numbers, not dex.
- Decode: lib/BCH.lua (relocate), lib/H3D.lua (models, materials, bones, skinning), lib/PICA.lua (textures), lib/GF1Motion.lua. lib/ORASActorCache.lua bakes species into mod cache oras/pokemon/<dex>/ (rev.txt stamp "oras-actor=8"; bump C.STAMP on layout change; cache ~3.4 GB at =7, about twice that with paged actions). lib/ORASRuntime.lua installs PokemonActors without the Colosseum runtime. Drawn by lib/PokemonActors.lua (sc.source == "ORAS").
- Flames: meshes whose texture is not the species' own (pmNNNN prefix) and is an intensity format (L8/A8/LA4/L4/A4) become GLOW groups: colour hardcoded by texture name (glowColor, "Fire"/"Core"), drawn additive + unlit, no depth write, after the body. Other non-own meshes are skipped. H3D does not decode material blend/stencil/constant colours yet.
- Battle motion pack (block +6, part 1) has 28 slots: 0 idle A, 1 idle B, 2 idle C, 3/4/5 send-out drop/land/recover, 6 flyer send-out, 8-11 physical, 12-15 special, 16 damage, 17 faint, 18 material-only loop (fire species, Zygarde), 25 cry (jaw only, 70 frames). Part 2 = 18 per-motion bounding boxes (6 floats each); parts 3.. = per-motion BCH material/visibility anims; SESD parts = sound timing. Block +7 (PK) is a 36-slot non-battle pack (Amie/refresh).
- Baked actions: physicalA-D, specialA-C, damage, faint, appear (chain 3+4+5, else 6), cry (25 layered over idle), idleB (1). One-shot banks are dense pages (ACTION_FRAMES_PER_SLOT = 3 source frames per pose) and carry jointPositions/jointFrames for every model bone (base.lua has boneNames). PokemonActors plays cry after appear and idleB every 3-5 idle loops (A.orasExtras = false turns both off).
- Mesh-node visibility: some species swap parts per motion (Pidgey's folded wings LWingCloseSkin/RWingCloseSkin vs open wings). Visibility anims are battle-motion parts slot+3 (BCH visibilityAnimations, H3D.visibilityAnimations/sampleVisibility); a mesh's nodeIndex names a visibility node, default visibility is model +7C bits, node names +8C. visibilityFor bakes meta.orasVisibility = {groupNode, nodeNames, tracks[action] = {frames, nodes[node] = "1110.."}} (switching nodes only, meta.visibilityVersion = 1); Actor:orasHiddenGroups() skips hidden groups at draw. Open wings in idle/damage/physical are hidden by bone scale 0 (LArm..RHand), not by visibility. Confirmed in game 2026-11-01.
- Cry layering: the `over` cry keeps only cry curves that really move (curveMoves); a flat keyed channel (Growlithe Waist rz = 1.57) laid over idle's other rotations tipped the body on its side. meta.cryFix = 1; older species whose cry has a flat channel are rebuilt by ORAS MODELS (~90). Confirmed in game.
- Offline probe: a lovec harness can open the dump directly (fake mod.imports over io.open on <save dir>/bundlemods/Terrarium Advance Mod/pokemon_oras.3ds) and call ORASActorCache.buildSpecies with a fake mod.cache.
- Compact banks: ORASActorCache writes every pose bank as "OQ16" (int16, per-file scales, slot deltas wrapped to 16 bits, zlib, padded to a multiple of 176 bytes so size checks pass; same .f32 names). RuntimeMeshCache.meshFromBytes decodes it (decodeQ16); plain float banks still load. About 28% of the float size, max error ~0.0005 units. Species already built are converted in place on the next ORAS MODELS run (marker oras/pokemon/<dex>/q16.txt = "oras-q16=2"; "=1" was written by a run that converted nothing and does not count; C.compactBanks = false skips). Bank listing walks mod.cache.storage.root directly: mod.cache:list is empty in game.
- Attachment points: lib/ORASBodyMap.lua maps the 16 PKX body slots from boneNames (entries: 0-based bone or {a,b} midpoint); Actor:bodyMap() uses it for ORAS scenes, Actor:attachment() resolves pairs.
- Hit sync: Actor:orasContactWait() = contact phase of the current physical bank (furthest +Z reach of body-core joints, 15-85% else 45%); CurrentSpriteModels passes it as Actor:hit opts.holdFor, the target holds the reaction (heldHit) until then (max 1.2 s).
- Packing: CacheArchive kind "oras" packs oras/pokemon/<dex>/* into cbe_cache_archive/oras/<dex>.cbeu (index cache/archive_v1/oras.lua; delete both or neither). index.lua and per-dex rev.txt, q16.txt, model_cache.lua, metadata_v1.lua stay loose. Packing drops the old unpaged action banks. ORASRuntime hooks its own GeneratedAssets via CacheArchive.install(G). Packed from OPTIONS -> ORAS PACK (row under ORAS MODELS, lib/ORASModels.lua), independent of the Colosseum PACK CACHE menu; a build repacks only an already-packed install.
- Reading cached files from ORASActorCache: always readCache (GeneratedAssets, else loose mod.cache, else mod.exports.cacheArchive.readEntry). mod.cache sees only loose files, and in game this module gets the mod's main V, which has no GeneratedAssets (that lives in the Colosseum namespace). Reading base.lua any other way makes every packed species look current and skips it silently (empty oras/build.txt).
- Move effects, data (dump GARCs): a/0/3/4 = 976 SESD move timelines (member = move + 119; 0-119 non-move, 741+ mega/trainer/gym intros); a/0/3/1 = 2040 CGFX particle files (names ewNNN_* for move NNN, etxp_* textures); a/0/3/2 = BCH effect meshes (not used yet); a/1/5/2 = arenas (next step).
- SESD (lib/ORASWazaSeq.lua): header "SESD", u32 2, u32 0, u32 frames; records u32 start, u32 end, u16 slot ("target" field = effect SLOT, not side), u16 group, u16 op, args with no length (OPLEN table learned from all files; 621/621 move timelines parse). Ops: 0x2B spawn particle file (u32 a/0/3/1 member) into the slot; 0x2F attach the slot (u32 0 attacker / 1 target, u32 body point, vec3 offset in cm, u32 easing) -- a later or timed 0x2F on a live slot = the effect FLIES there (155 moves, e.g. Ember, Fire Punch); 0x34 slot scale vec3 (Thunderbolt 2.5, Ember 1.5/3, Water Gun 0.01 -> 2); 0x0C with u32 1 = the target's damage cue (509 moves; Tackle 22, Ember 36, Thunderbolt 45, Thunder 90); 0x64/0x5D sound (u16 id, bank 13, volume) and 0x68 its placement; 0x76 screen fade/flash?; 0x17 camera? (last three not played yet). Body points: 0 feet, 2 mouth, 5 body centre (sure); 3/4/6/8/15/16 mapped by guess (ORASEffectsPlayer POINT_SLOT).
- Particles (lib/ORASParticles.lua, CGFX): DATA dicts Models[0] CMDL particle model, Textures TXOB, Emitters PEMT. Particle set = CNOD 0x40000001: +0x30 constant attribute table (life, rotation, texcoord scale for flipbooks), +0x34/+0x38 initializers, +0x3C/+0x40 updaters, +0x44 orientation (0x80000000 camera billboard, 0x20000000 upright/streak, 0x10000000 flat quad with local height on +Z; pivot y -1 = grows from its bottom). Entries = u32 flag, u32 0x100, s32 attr, values; attrs 0 position, 1 scale, 2 rotation, 3 colour, 4 alpha, 5 flipbook frame, 8 scale over life, 11 life, 12 velocity. Keyed curves: updater 0x100000 (vec3) / 0x200000 (16.16 float): tIn, tOut, v0, v1, sIn, sOut. PEMT: +0x30 scale/rot/translate, +0xB8 set name, +0xBC spawn shape (point/disc/sphere/cylinder/rect; raw [2] inner fraction, [3] arc, [6..8] size), +0xC4 ratio, +0xCC interval, +0xD8 duration (360 = loop), +0xDC delay. Material MTOB +0x148 = PICA blend (0x16160000 add, 0x76760000 alpha); texture name at its TXOB ref +0x18; material = <set>Material. All 2040 files / 8407 sets / 6517 emitters / 5974 textures read. Not decoded: child emit (updater 0x4000000), field updaters on attr 0, keyed tables 0x800001/0x800002, attr 6/7 details.
- Simulator (lib/ORASParticleSim.lua): Sim.new/step/quads/done/stopEmitting, 30 fps, seeded RNG; emitter rotation applied to spawn point and starting velocity; quads carry velocity.
- Bake (lib/ORASEffects.lua): OPTIONS -> ORAS EFFECTS (row under ORAS PACK; own pump in main.lua) -> mod cache oras/movefx/: index.lua (stamp oras-fx=4; moves[move] = {frames, hit, fx = {{start, end, slot, member, role, point, off, scale = {{frame, x, y, z}}, travel = {{f0, f1, role, point, off, easing}}}}}, members[m] = role), fx/<m>.lua, tex/<name_WxH>.png. ~4-10 s, 604 moves, 1429 files, 177 textures, ~7 MB, loose (no pack kind yet). Bumping the stamp makes the row show BUILD again. Rows: ORAS FX IN BATTLE (ON/OFF, oras/movefx/battle.txt, default ON), ORAS FX SIZE (x1/x2/x3, oras/movefx/size.txt, default x2: grows quads only, not the spread).
- Player (lib/ORASEffectsPlayer.lua): runs a move timeline at 30 fps (wall clock, driven by ORASEffects.pump) on a host {point(role, slot), forward(), unit()}; side from 0x2F (else 0x68, else '_at_'/'_df_' names); anchor = body point + offset, moved along travel phases; unit = an ORAS actor's worldScale * posed height / nativeHeight (effects are in cm; Pikachu 37.4 cm); per-slot scale x ORAS FX SIZE; upright quads point along their velocity. Player.hitWait = seconds to the move's hit cue (else first target effect).
- Hooks: CurrentSpriteModels (Colosseum battle screen and the arena host's 3D-BTL COLOSSEUM pass) starts a run at battle.move_used when ORAS FX are on and an ORAS actor is out, skips the Colosseum attack/damage FX for that move, holds the target's hit (Actor:hit holdFor = hitWait), and drawOrasFx draws both 'csm' and 'scene' runs (one draw per run per frame). lib/ORASEffectsScene.lua hooks BattleState.performMove for every 3D-BTL rung (2D-3D A/B, STADIUM, COLOSSEUM; with or without the Colosseum runtime) and draws into BattleScene's 3D canvas with Voxel3D.vp -- that draw is NOT verified to show (in COLOSSEUM A only the CSM pass was seen to draw); in staged fights CSM leaves starting to it. 3D actors: ORAS models given a Colosseum per-move slot they lack now play their own physicalX/specialX (PokemonActors Actor:attack).
- Stage records (lib/ORASStage.lua, bake stamp oras-fx=5, entry.stage; 550 moves, 7 with no particles): 0x02 (who, dx, dy, dz cm) move the actor over the span, 0x03 (who, mode, ?, dx, dy, dz, ease 1/2) the same eased, 0x04 (who) back home + size 1, 0x08 (who, sx, sy, sz) squash/stretch, 0x76 (r, g, b, a) stage colour (Double Team 0.8 black, Agility purple, white flashes), 0x17 (who 0/1/2, point, eye xyz, look xyz cm in that side's frame) camera. Side frame: x right, y up, z toward the other side (same basis as ORASEffectsPlayer). 0x63 is the same in every move (1.0, 11.3, ...): the 11.3 deg lens, used as the camera fov while a move camera runs. Runs stay alive to max(frames, last stage record) + 10 frames; camera and tint ease back over those 10. Afterimages: Double Team (move 104) hops 0 / +50 / -50 cm every frame (45-70) -- when the last 5 frames turn back twice, the model stands at the middle of its distinct places and each other place gets a ghost (alpha 0.45, Stadium.drawGhosts, actor.ghostDraw = no depth write). Particle file 5 (ea004_line, etxp_wind04) is only speed lines; 0x3A (27.0, 1, 0) on generic particles is not decoded. Hooks: Stadium.update (model_matrix + actor.worldMatrix via ORASEffectsScene.adjustMatrix, so effects follow the body), Stadium.drawGhosts, BattleScene monCards (2D cards move, no ghosts), BattleScene camera (ORASEffectsScene.camera before letterboxFov; frames the side's cell, not the hopping body), BattleScene stage tint (Voxel3D.flatten before the stage, reset before the Pokemon). 3D-BTL only; the Colosseum battle screen (CSM space) ignores stage records. Unmapped: 0x0D (who, motion id), 0x75 (on/off, rgb), 0x3A; Fly turn 1 snaps home at frame 10 (likely a hide op not read yet).
- Move cameras vs BattleScene (fixed 2026-11-02 after the first in-game test): BattleScene.render returns nil when toGB has no answer for a mark (behind the lens), and OverworldBattle then shows the flat GB battle -- every ORAS close-up has the other side behind the camera. Now the move camera draws the 3D shot only; the marks (player/enemy, spans), shot.vp/eye/focus come from the battle's own camera (baseCam/anchorVp), and shot.dofY gives BattleDOF the move camera's marks when both are in front. ORAS stands the two Pokemon further apart than our cells (~305 cm at Pikachu's 0.157 units/cm), so its close-ups put the eye inside the other Pokemon: ORASEffectsScene.camera slides the eye toward its target until it is 0.4 x the cell gap from both cells (scan, MIN_PULL 0.25) and opens the lens by the same ratio (11.3 deg / t, max 60); eye kept >= ground + 2; the camera frames a side's cell, subtracting the hop only from an actor's body point. F12 'camera:' line per run.
- F12 report: '3D-BTL staged / rung' and an 'ORAS FX' section (running runs with anchor, unit, scale, which path drew them; recent events: starts, refusals with reason, hit holds). ORASEffects.pump also polls F12, so fights with no 3D actor dump too.
